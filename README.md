# Door Puzzle Prototype

Unity 6, одна игровая сцена `Assets/Scenes/Main.unity`. Каждый из двух уровней
содержит четыре последовательно проходящие головоломки. Дома создаются во
время игры из конфигов в `Assets/Scripts/LevelCatalog.cs`.

## Конфиги

`PuzzleConfig(roomCount, doorCount, deadEndCount, branching, seed, visualTheme, ...)`:

- `doorCount` включает дверь выхода;
- `deadEndCount` — число комнат с одной внутренней дверью, кроме комнаты выхода;
- `branching = 0` — без дополнительного требования, `1` — хотя бы одна комната
  с тремя дверями, `2` — хотя бы одна комната с тремя разными соседями;
- `seed` фиксирует результат генерации, включая последовательность повторных
  попыток;
- `visualTheme` определяет цвет пола.
- `allowLeafRooms` разрешает комнаты с одной **внутренней** дверью только для обучения;
- `minRoomDegree` задаёт минимум внутренних дверей в каждой комнате; EXIT не считается;
- `preferredStartMinDegree` требует хотя бы один выигрышный старт с такой степенью;
- `minBranchingRooms` задаёт число комнат хотя бы с тремя внутренними дверями;
- `minWrongStartSurvivalMoves` требует, чтобы хотя бы из одного неверного старта
  можно было пройти столько внутренних дверей до реального тупика.

в другой комнате со степенью 3.

## Как создаётся задача

`PuzzleGenerator` строит логический граф: комнаты — вершины, двери — рёбра.
Сначала выбирается путь, проходящий через все комнаты, затем добавляются двери
между соседними клетками сетки. Допускаются две двери между парой комнат. Для
выхода выбирается внешняя стена. Генератор проверяет степени и ветвления;
обычные задачи также обязаны содержать цикл между разными комнатами. После
этого комнаты и двери размещаются на сетке 3×3.

`PuzzleSolver.FindWinningStarts` перебирает стартовые комнаты и маршруты с
помощью DFS с возвратом. Задача принимается, только если найдён маршрут через
каждую дверь ровно один раз с EXIT последним. Если схема не подходит, генератор
пробует другой вариант с производным от `seed` значением; максимум — 256
попыток с полными требованиями и 256 с ослабленными предпочтениями. Минимум
двух внутренних дверей сохраняется. Несовместимое количество дверей и комнат
корректируется с предупреждением в Console. Если и ослабленный поиск не
помог, используется проверенная схема с циклом и без комнат с одной дверью.
Во время игры `PuzzleSolver.IsDeadEnd` сообщает о проигрыше, когда
EXIT закрыт рано или открытые двери стали физически недостижимы.

## Изменение и добавление задач

Измените числа в нужной строке `LevelCatalog.cs`. `roomCount` сейчас может быть
от 3 до 9, а `doorCount` должен быть хотя бы `roomCount + 1` и не больше 30.
Число дверей может быть повышено или снижено генератором до допустимого для
заданного числа комнат и сетки 3×3. Для обычных задач с нечётным числом комнат
требуется как минимум `roomCount + 2` дверей вместе с EXIT. Чтобы
добавить Puzzle 5, добавьте ещё один `new PuzzleConfig(...)` в нужный
`GameLevelConfig`. Счётчик `PUZZLE N/M` и переходы подстроятся автоматически.

## Ручная проверка в Unity

1. Откройте `Main.unity` и запустите Play. На каждом доме должна быть надпись
   `CHOOSE START ROOM`; нажмите любую комнату.
2. Проверьте, что выбранная комната получает персонажа, а двери закрываются
   после прохода. Ранний EXIT и реальный тупик должны давать `YOU LOSE`.
3. Пройдите каждую задачу. После четвёртой задачи первого уровня должно
   появиться `LEVEL COMPLETE`, после четвёртой задачи второго — `GAME OVER`.
4. Нажмите Restart посреди задачи: должны обнулиться только текущие двери и
   снова появиться выбор стартовой комнаты. Для проверки времени прохождения
   измерьте несколько попыток на телефоне; заданные 5–15 и 15–30 секунд
   зависят от игрока и пока не ограничиваются таймером.
